# Stateful interaction and form parity v8

This phase makes common pointer, keyboard, control, and application-update workflows behave like equivalent HTML applications. Work proceeds one browser behavior at a time: add a deterministic real-input fixture, capture the unsupported baseline, implement the general scene-owned behavior, compare state/event/geometry/text/paint after every action, run the full corpus, document the supported boundary, and commit the increment.

## Completion thresholds

- The harness drives real pointer and keyboard input in the existing browser page and Babylon scene and compares normalized event order, focus, supported control state, geometry, text, and screenshots after every action.
- All three representative applications contain useful interactive workflows with pointer and keyboard coverage; at least one continues through responsive resize and application-data update.
- Stable compatible authored IDs preserve supported control state through reflow/update; removed or incompatible controls blur and clean up.
- Repeated interaction/update/resize/dispose cycles do not grow scene resources, observers, listeners, action registrations, focus/cursor/selection/dropdown meshes, or registries.
- No executable event-handler strings are used by the supported public path.
- Full-corpus median SSIM remains at least `0.98`; every representative viewport remains at least `0.95`; at least `95%` of edges are within `2px`; no unexplained error exceeds `5px`; visible text and line counts match exactly.
- Supported normalized interaction state and event logs match exactly, runtime/lifecycle/disposal reports are clean, all tests and both builds pass, commits are incremental, and the final clean commit passes `npm run parity:check` three consecutive times unchanged.

## Starting baseline

The unchanged Phase 7 commit `32d031a` passes 132 tests, the library build, and the production application build with only the two documented size-budget warnings. Its enforcing parity result is 103 fixtures / 137 renders / three viewports; median SSIM `0.9952`; minimum `0.9509`; `99.9%` of measured edges within `2px`; maximum error `3.9921px`; exact visible text; clean runtime and completion thresholds.

The legacy renderer creates visible controls and contains several root-scoped input/focus/action services, but `AstylarRenderOptions` has no typed application event channel. Input setup also owns global keyboard and scene observers outside the render session, and `DOMElement.onclick` is a string-valued legacy field. These paths are evidence to reconcile, not an accepted public interaction contract.

## Supported public interaction boundary so far

- Executable functions remain outside JSON `SiteData` in `AstylarRenderOptions.events.handlers`, keyed by stable authored element ID and event type.
- `events.onEvent` observes one normalized snapshot after each completed dispatch.
- Pointer targeting walks the picked Babylon mesh hierarchy to the authored element ID, so text/indicator child meshes retain their control target.
- Pointer focus and forward/reverse Tab navigation support buttons, inputs, textareas, selects, and anchors with `href`; disabled, hidden, and negative-`tabindex` controls are omitted. Positive `tabindex` values precede normal authored order.
- Focus, blur, keydown, and keyup use the same typed dispatch channel. Cancelling pointerdown prevents its focus default; cancelling Tab prevents navigation; cancelling a control key prevents its default action.
- Text inputs and textareas support printable-key insertion, Backspace/Delete, Home/End and arrow caret movement, ordered DOM-style selection endpoints, selection replacement, immediate `input` after value mutations, and edited-value `change` before blur. Textareas additionally preserve Enter-created blank and trailing lines.
- Checkbox pointer activation applies the tentative checked state before `click`, emits `input` then `change` after an accepted mutation, and restores state without mutation events when `click` is cancelled. Missing checkbox values use the browser default `on`.
- Radio pointer activation applies exclusive named-group state before `click`, emits mutation events only when the selection changes, and restores every group member when `click` is cancelled. Arrow keys move focus and selection among enabled named-group members with wrapping and browser-order synthesized activation events.
- Checkbox and radio Space activation is deferred until after keyup, then follows the same reversible `click`, `input`, and `change` path as pointer activation.
- Closed single-select controls support ArrowUp/ArrowDown selection, disabled-option skipping, immediate display refresh, and browser-order `input` then `change`; the custom expanded-popup path remains separate.
- Enabled buttons support browser-timed Enter and Space synthesized clicks through the typed API; disabled buttons receive neither default activation.
- Stable-ID explicit labels with `for` focus and activate enabled associated controls after an accepted label click; implicit wrapping labels remain outside the measured subset.
- Reset inputs use button pointer/keyboard activation, dispatch a cancellable `reset` event on their containing form, and restore authored text, checkbox, radio, and select defaults without `input` or `change` events. Text selection follows the observed native blur distinction: pointer blur clears the reset caret, while Tab blur preserves and clamps it, including across compatible rebuilds.
- Submit inputs use button pointer/keyboard activation and dispatch a cancellable, bubbling `submit` event on their containing form after an accepted click.
- Explicit submit validates registered required text controls in authored order, emits non-bubbling `invalid`, focuses the first uncancelled invalid control, and suppresses `submit` until the controls are valid.
- Enter in an eligible single-line form field clicks the first enabled explicit submitter and follows the same validation/submission path while retaining field focus.
- Authored `:hover` paint applies on pointer entry and restores on leave; typed boundary events are scoped to declared authored targets.
- Authored `:active` solid background and opacity apply for the primary-pointer held interval and restore the exact pre-press material on release.
- Authored `:focus` solid background and opacity apply for the focused interval and restore normal paint on blur. A supported authored solid focus background replaces the fallback focus ring; broader focus properties and native outline emulation are not claimed.
- Stable, uniquely identified controls preserve applicable live state across non-initial update/reflow rebuilds when their semantic type and authored defaults remain compatible. Text entries retain value, focus, caret, directional selection, scroll offset, and supported validation state. Checkboxes/radios retain checked state, selects retain a still-present enabled selected value, non-text controls retain supported validation state, and compatible buttons/controls retain focus. Application-authored default changes take precedence; missing, duplicate, or incompatible controls do not receive stale state.
- A focused control that becomes missing, disabled/hidden, duplicate, or semantically type-incompatible commits supported edited text and blurs through the old event path before rebuild. Reusing its ID later starts from new authored defaults; repeated remove/re-add cycles restore exact resource and registry counts.
- The representative project dashboard exercises search editing, a filtered application-data update, mobile responsive reflow, explicit-label pointer activation, and checkbox Space activation as one browser-equivalent workflow while retaining live control state and stable scene registrations.
- The representative data-management application exposes its semantic table and positioned detail panel in all three viewports, then exercises search editing, pagination pointer/keyboard activation, page-data replacement, compatible state preservation, and record-action pointer/keyboard activation without mutating application scroll containers in the harness.
- The representative account-settings application exercises modal dismissal, focused application-data replacement, required validation and invalid-focus recovery, text editing, Tab navigation, closed-select keyboard selection, explicit-label checkbox activation, valid submit, and browser-equivalent form reset.
- Each active scene owns one pointer observer and a canvas keydown/keyup listener pair. Renderer rebuilds and disposal clean both listeners, pending activation, input registrations, focus state, cursor timers, and focus-ring meshes.
- The parity harness repeats equivalent interaction/update/responsive phases after cache warm-up and enforces non-growing resources plus exact registry and observer/listener/handler plateaus. It also disposes the interaction scene and requires zero remaining resources, elements, inputs, and cleanup registrations.
- The dispatcher supports target identity, current-target identity during propagation, value/checked/selected payloads, pointer/keyboard fields, `preventDefault()`, and `stopPropagation()`.
- `DOMElement.onclick` remains type-compatible but is deprecated and is not executed by the supported event path.

All three representative applications now have useful pointer/keyboard workflows, the project dashboard continues through both application-data update and responsive resize, and dedicated repeated interaction/update/resize/dispose stress coverage enforces lifecycle stability. Pointer-driven text selection, expanded-select pointer/keyboard defaults, checkbox/radio and broader constraint-validation nuances, implicit labels, and broader active/focus properties remain outside the supported Phase 8 boundary rather than blocking its real-use completion threshold.
