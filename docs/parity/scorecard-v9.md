# Scrolling, pointer selection, and popup interaction parity v9

This phase extends the stateful interaction foundation with production-usable overflow scrolling, pointer-driven text selection, text-control autoscrolling, and expanded single-select interaction. Work proceeds one bounded browser behavior at a time: add a deterministic real-input fixture, capture the unsupported baseline, implement the reusable scene-owned behavior, compare after every action, run all gates, document the boundary, and commit the increment.

## Completion thresholds

- Wheel and trackpad-style input scroll supported `overflow: auto` and `overflow: scroll` containers vertically and horizontally, with browser-equivalent limits, clipping, targeting, and nested propagation.
- Stable, unique, semantically compatible containers preserve and clamp offsets through update/reflow; removed, duplicated, disabled, or incompatible containers do not retain stale state.
- Pointer caret placement, bidirectional drag selection, selection replacement, supported Shift extension, and text-control autoscrolling keep value, selection, focus, paint, and events synchronized.
- Expanded single-select pointer and keyboard workflows support disabled-option skipping, commit/cancel, click-away dismissal, viewport-aware placement, targeting, stacking, and cleanup within the documented subset.
- All three representative applications contain useful Phase 9 workflows, and repeated scroll/selection/popup/update/resize/dispose cycles do not grow resources or registrations.
- Full-corpus median SSIM remains at least `0.98`; every representative viewport and required new fixture remains at least `0.95`; at least `95%` of measured edges are within `2px`; no unexplained error exceeds `5px`; visible text and line counts match exactly.
- Supported interaction and scroll state plus normalized event logs match exactly, runtime/lifecycle/disposal reports are clean, all unit tests and both builds pass, and the completed clean Phase 9 commit passes the enforced corpus.

## Starting baseline

The unchanged Phase 8 commit `75abecd` passes 166 tests, the library build, and the production application build with only the two documented size-budget warnings. Its enforcing parity result is 125 fixtures / 294 renders / three viewports; median SSIM `0.9932`; minimum `0.9512`; approximately `99.97%` of measured edges within `2px`; maximum error `3.9921px`; exact visible text and interaction state; clean runtime and lifecycle reports.

The Phase 8 interaction runtime owns pointer and keyboard input, focus, typed events, default actions, and compatible control-state restoration. It does not own a wheel listener or a scroll-container registry, `overflow: auto`/`scroll` content is not clipped or translated, and the parity report has no deterministic scroll state.

## Supported public Phase 9 boundary so far

- Unique, stably identified elements with authored `overflow: auto` or `overflow: scroll` are registered as scene-owned scroll containers after rendering.
- Pixel, line, and page-mode wheel deltas are normalized by the interaction runtime. A consumed wheel movement prevents the native canvas/page default; an unconsumed movement remains available to an ancestor or host page.
- Vertical offsets clamp to the measured content range and translate authored direct child roots beneath a stationary clip.
- Horizontal offsets clamp to the measured content range and account for the camera's reversed screen-X projection while translating authored content beneath the same stationary clip.
- Wheel targeting begins at the picked descendant and walks authored ancestors to find a scroll container.
- A scrollable descendant consumes an axis while it can move; once it is exhausted in that direction, the next wheel event walks onward to and scrolls the nearest eligible ancestor. Reverse movement returns to the inner container until its opposite boundary is reached.
- Nested world-space clipping intersections are recomputed after completed layout and every consumed scroll transform, so normal-flow placement and moving ancestors do not leave stale clip planes.
- Pointer hits on descendants outside any registered ancestor scroll bounds are rejected, so clipped content cannot be activated.
- Pointer focus and activation are owned only by the clip-aware scene interaction runtime; legacy mesh pick defaults no longer bypass scroll visibility. A focused control may remain focused while scrolled out, and an accepted click on the exposed background blurs it as in the browser.
- The current offset is restored after a compatible stable-ID rebuild and clamped if the rebuilt content range is smaller. Duplicate container IDs are not restored or registered.
- Browser coverage now verifies that a sibling-only application-data update preserves a live offset and that a compatible shorter-content replacement clamps it to the rebuilt maximum.
- Current authored cascade resolution determines each rebuilt container's eligibility. Hidden/removed/duplicate identities are absent from the supported registry, and a later unique compatible-looking reuse starts at zero because the intervening lifetime was not compatible.
- Each active scene owns one wheel listener and one scroll registry. Disposal removes the listener and clears the registry.
- The parity harness drives real wheel input and compares deterministic container offset, scroll extent, and client extent after every measured action.
- Real pointer actions can target deterministic CSS-pixel offsets within independently measured HTML and Astylar boxes. Single-line inputs use their text metrics to collapse the caret and public ordered selection endpoints to the nearest browser-equivalent boundary.
- Pointer drags support forward and backward selection in text inputs. Ordered public endpoints, internal anchor/focus direction, selection replacement, focus transfer, and edit commit events remain synchronized.
- Long single-line inputs expose CSS-pixel horizontal text scroll state and keep the caret/selection visible through keyboard movement and editing; compatible rebuild restoration remains covered by the existing text-state lifecycle path.
- Overflowing textareas use their full client viewport while retaining authored padding in scroll coordinates. Exact multiline select-all, directional range collapse, editing at a scrolled caret, pointer/cursor/highlight coordinate mapping, and compatible `scrollTop` restoration share one CSS-pixel state model.
- Textareas support ArrowUp/ArrowDown and Shift extension across visual lines. Consecutive vertical moves retain a proportional-font preferred X, the active focus drives viewport scrolling, and pointer/horizontal/exact selection changes reset the vertical goal.
- Pointer drags remain captured by their originating text control after leaving its mesh. Off-mesh rays are projected onto the active text plane without viewport clamping, and pointer-owned multiline selections retain the native scroll state independently from keyboard caret autoscrolling.
- Enabled single-selects expose deterministic expanded state after pointer opening. Their popup uses compact font-relative rows with native-like selected/disabled treatment, and Escape cancels without value mutation or a page-visible keydown.
- Expanded single-select arrows move a separate active option, skip disabled choices, preview that option in the field, and leave committed value/index unchanged. Enter commits once with native event order; popup-owned arrow keydown/keyup events are not exposed to application handlers.
- Enabled popup rows are captured and committed by the scene-owned pointer runtime. Their internal pointer sequence is not retargeted to page handlers; a changed choice emits `input` then `change`, closes the popup, and leaves the select focused.
- Clicking outside the select, display, popup, and option descendants dismisses the popup without mutation. A non-focusable outside target clears select focus and emits `blur` at the browser boundary.
- Popup vertical placement uses the control's projected CSS-pixel viewport position. It opens above when below-space is insufficient and above offers more room; otherwise it retains normal below placement.
- Expanded popup rows and the popup subtree take pointer priority over overlapping authored page meshes, matching native top-layer targeting while keeping popup pointer events private from application handlers.
- Popup lifecycle reporting enforces one click-away observer and positive transient mesh/material/texture counts for each expanded select, and zero popup ownership for closed, removed, or replaced controls. Disposal removes popup observers immediately and releases mesh-local popup materials.
- Authored `:focus`/`:active` border colors participate in the same immediate pseudo-state paint switch as control backgrounds and return to their normal shared border material when the state clears.
- Deterministic interaction comparison now enforces native integer `scrollLeft` for all text controls and `scrollTop` for textareas, including explicit zero state for empty controls.

Representative Phase 9 workflows and the combined Phase 9 lifecycle stress sequence remain to be implemented and verified before this phase is complete.
